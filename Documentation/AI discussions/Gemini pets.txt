The Attachment Memory Scan

The 12 attachment slots start shortly after the head/frame offsets in the structural block. In standard client layouts, they are grouped as a block of
14 slots (12 active slots + 2 buffers/historic padding).

You can inject a function like this into your LuAshitacast script to scrape them programmatically:

    local function GetEquippedAttachments()
        local pet_info_ptr = AshitaCore:GetMemoryManager():GetPlayer():GetPetInfoPointer();
        if (pet_info_ptr == 0) then
            return {}; -- No pet out or memory pointer not populated
        end

        -- The array offset for active attachments typically starts around 0x40 to 0x44
        -- depending on the exact client build.
        -- We read 12 sequential uint16 (2-byte) item IDs.
        local attachment_array_offset = 0x40;
        local raw_bytes = ashita.memory.read_array(pet_info_ptr + attachment_array_offset, 24); -- 12 slots * 2 bytes

        local attachments = {};
        if (raw_bytes ~= nil) then
            for i = 1, 12 do
                -- Reconstruct the uint16 ID from the byte pairs
                local low_byte = raw_bytes[(i - 1) * 2 + 1] or 0;
                local high_byte = raw_bytes[(i - 1) * 2 + 2] or 0;
                local item_id = low_byte + (high_byte * 256);

                if (item_id > 0) then
                    table.insert(attachments, item_id);
                end
            end
        end

        return attachments; -- Returns a clean array of active attachment item IDs
    end

How to Structure the Cache

Instead of sniffing packets to detect the change, you can leverage Ashita's native state changes. You only need to clear or recalculate your cache when gData.GetPet() changes its pointer or targets.

Here is a clean, optimized way to cache that specific calculated property right inside your profile:

    -- Create a local cache structure at the top of your script
    local petCache = {
        id = 0,
        hasPet = false,
        petType = 'None' -- 'Avatar', 'Spirit', 'Jug', 'Charmed', 'Automaton', 'Wyvern'
    };

    -- Your heavy calculation function (runs only when the pet actually changes)
    local function calculatePetType(pet)
        -- Put your existing logic here:
        -- e.g., local spawnFlags = pet.SpawnFlags (or however you pull it via Ashita memory)
        -- e.g., if bit.band(spawnFlags, ...) then ...

        -- Return the determined string type
        return 'Avatar'; -- (Placeholder for your actual logic)
    end

    local function getPetType()
        local currentPet = gData.GetPet();

        -- Case 1: No pet out
        if (currentPet == nil) then
            petCache.id = 0;
            petCache.hasPet = false;
            petCache.petType = 'None';
            return petCache;
        end

        -- Case 2: The pet changed (or was newly summoned)
        if (currentPet.Id ~= petCache.id) then
            petCache.id = currentPet.Id;
            petCache.hasPet = true;
            -- Run the heavy bitwise / modelId calculation ONCE here
            petCache.petType = calculatePetType(currentPet);
        end

        -- Case 3: Pet is the same, return the cached results instantly O(1)
        return petCache;
    end
