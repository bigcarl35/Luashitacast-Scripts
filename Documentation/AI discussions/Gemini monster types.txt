Since some names contain escaped single quotes (like \'), the previous basic pattern will break because it stops capturing at the very first single
quote it encounters.

To fix this, you need a pattern that accounts for the backslash escape character. Here is the updated Lua script that uses a robust pattern to handle
escaped quotes perfectly.

    -- Sample lines including your escaped quote example
    local lines = {
        "['Bo\\'Who Warmonger']       = { Name='Bo\\'Who Warmonger', Ecosystem='beastmen', Family='orcs' }",
        "['Goblin Weaver']       = { Name='Goblin Weaver', Ecosystem='beastmen', Family='goblins' }"
    }

    -- The robust pattern to handle optional escaped single quotes
    -- It captures anything that is NOT a quote, OR a backslash followed by any character
    local pattern = "Name='((?:[^'\\]|\\.)*)'.-Ecosystem='((?:[^'\\]|\\.)*)'.-Family='((?:[^'\\]|\\.)*)'"

    -- Note: Standard Lua patterns don't support alternation (like |).
    -- If you are using standard Lua without extensions, we solve it using an elegant match-and-clean approach:

    for _, line in ipairs(lines) do
        -- 1. Temporarily swap out escaped quotes so they don't break the pattern
        local safe_line = string.gsub(line, "\\'", "___ESCAPED_QUOTE___")

        -- 2. Extract using the simple pattern
        local name, ecosystem, family = string.match(safe_line, "Name='([^']*)'.-Ecosystem='([^']*)'.-Family='([^']*)'")

        if name and ecosystem and family then
            -- 3. Restore the escaped quotes back to their original form
            name = string.gsub(name, "___ESCAPED_QUOTE___", "\\'")
            ecosystem = string.gsub(ecosystem, "___ESCAPED_QUOTE___", "\\'")
            family = string.gsub(family, "___ESCAPED_QUOTE___", "\\'")

            print("Name: " .. name .. " | Ecosystem: " .. ecosystem .. " | Family: " .. family)
        end
    end

Why the Match-and-Clean Approach is Best

Standard Lua string patterns are highly lightweight but lack advanced Regex features like alternation (|) or lookarounds. By temporarily replacing \' with a
unique placeholder string (___ESCAPED_QUOTE___), you can still use Lua's native string.match safely without needing to install external heavy regex libraries \
like luaposix or lpeg.

To prevent missing or unmapped zone IDs from throwing fatal Lua execution errors that freeze your entire LuaShitacast script, you can wrap your loader
in a pcall (protected call).

If pcall catches an error (like a missing file), it halts the error silently and hands control back to your code. Here is the bulletproof, cross-platform
implementation:

Safe Zone Loader with pcall

    local current_zone_monsters = {}

    function load_zone_data_by_id(zone_id)
        -- 1. Early exit rule for unassigned, zero, or invalid zone IDs
        if not zone_id or zone_id <= 0 then
            current_zone_monsters = {} -- Clear old data safely
            return
        end

        -- 2. Build cross-platform path string
        local clean_path = string.gsub(_addon.path, "\\", "/")
        local path = string.format("%sdata/%d.lua", clean_path, zone_id)

        -- 3. Execute loadfile inside a protected call to catch file-missing errors
        -- pcall returns: success status (true/false), and either the loaded chunk or the error message
        local load_success, chunk_or_err = pcall(loadfile, path)

        if not load_success or not chunk_or_err then
            -- File doesn't exist, is unreadable, or contains syntax errors.
            -- Wipe the table so you aren't accidentally tracking monsters from the previous zone.
            current_zone_monsters = {}
            -- Log a clean, non-crashing message to your Ashita console
            print(string.format("[Zone Tracker] No valid data file found for Zone %d. Lookup bypassed.", zone_id))
            return
        end

        -- 4. If the file loaded successfully, run it inside another pcall
        -- This prevents syntax/runtime errors inside your data layout from crashing your script
        local run_success, data = pcall(chunk_or_err)

        if not run_success or type(data) ~= "table" then
            current_zone_monsters = {}
            print(string.format("[Zone Tracker] Critical: Data file for Zone %d failed to execute properly.", zone_id))
            return
        end

        -- 5. Data is safe to flatten
        if data.eco then
            for eco_name, families in pairs(data.eco) do
                for fam_name, monsters in pairs(families) do
                    for _, monster_name in ipairs(monsters) do
                        current_zone_monsters[string.lower(monster_name)] = {
                            ecosystem = eco_name,
                            family = fam_name
                        }
                    end
                end
            end
            print(string.format("[Zone Tracker] Successfully initialized data mapping for Zone %d.", zone_id))
        end
    end

How this Handles BCNMs & Special Cases

    - Graceful Degradation: If you step into a BCNM zone that has no corresponding .lua file, the script clears current_zone_monsters and prints a single
      warning line. Your PreCast script will still run perfectly—it will just drop down to its fallback code (letting spells through normally).

    - Sanity-Checked Execution: If you make a syntax typo while manually writing a data file (like forgetting a comma in the table layout), the second
      pcall will intercept the break and block the crash.
