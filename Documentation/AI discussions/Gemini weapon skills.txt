me: on horizonxi using luashitacast or ashitacore directly, are there ids associated with weaponskills?

Yes, there are numerical IDs explicitly associated with weaponskills when using both LuAshitacast and AshitaCore directly on HorizonXI. These IDs are inherited
directly from the standard Final Fantasy XI data structures (e.g., Savage Blade is ID 240, Asuran Fists is ID 32, etc.)

1. In LuAshitacast (LAC)

When a weaponskill is executed, it populates a global action/spell table passed into functions like profile.OnPrecast. You can capture and read the ID via the
action object:

    profile.OnPrecast = function(action, bSpells)
        if (action.Type == 'Weaponskill') then
            local wsId = action.Id
            -- alternative syntax depending on LAC version: action.Resource.Id

            if (wsId == 240) then
                -- Logic specifically for Savage Blade
                gFunc.EquipSet(sets.SavageBlade);
            end
        end
    end

2. Accessing Directly via AshitaCore

If you are writing an addon/plugin from scratch or bypassing LuAshitacast, you pull this data from Ashita's Resource Manager:

    - By ID: AshitaCore:GetResourceManager():GetWeaponSkillById(id);

    - By Name: AshitaCore:GetResourceManager():GetWeaponSkillByName(name, language);

Example of checking the current action packet or parsing a weaponskill:

    local resource = AshitaCore:GetResourceManager():GetWeaponSkillById(240);
    if resource ~= nil then
        print(resource.Name[1]); -- Outputs the English name (e.g., "Savage Blade")
    end

me: I currently track a list weaponskills based on the stats that affect damage. I use the weaponskill names, but I suspect Ids would be more efficient.

Switching your tracking system to numerical IDs is significantly more efficient than matching text strings. In Lua, integer lookups in a table are instantaneous
hash lookups, whereas string comparisons require evaluating characters sequentially, which consumes more overhead over hundreds of combat cycles.

Performance & Structural Advantages

Using IDs instead of names provides major advantages for LuAshitacast tables:

    - Zero String Parsing: It bypasses standard string overhead entirely.

    - Typo Prevention: It eliminates bugs caused by spelling mistakes or extra spaces (e.g., "Savage Blade " vs "Savage Blade").

    - Unified Stat Grouping: You can restructure your table so multiple weaponskills that share the exact same stat modifiers point to a single gear set profile.

Recommended Lua Structure

Instead of creating a giant if/elseif chain for every single weaponskill name, you can map the Weaponskill IDs directly to their primary stat scaling modifiers
inside a lookup table:

    -- Group your weaponskills by their primary scaling stat IDs
    local ws_modifiers = {
        -- STR Modifiers
        [32]  = 'STR', -- Asuran Fists
        [240] = 'STR', -- Savage Blade (HorizonXI relies heavily on STR/MND, map to primary)

        -- DEX Modifiers
        [17]  = 'DEX', -- Raging Fists
        [43]  = 'DEX', -- Evisceration

        -- AGI Modifiers
        [179] = 'AGI', -- Sidewinder
        [181] = 'AGI', -- Arching Arrow
    }

    profile.OnPrecast = function(action, bSpells)
        if (action.Type == 'Weaponskill') then
            -- Find the primary modifier category using the ID
            local modifier = ws_modifiers[action.Id]

            if (modifier == 'STR') then
                gFunc.EquipSet(sets.WS.STR);
            elseif (modifier == 'DEX') then
                gFunc.EquipSet(sets.WS.DEX);
            elseif (modifier == 'AGI') then
                gFunc.EquipSet(sets.WS.AGI);
            else
                -- Fallback default weaponskill set if ID isn't explicitly mapped
                gFunc.EquipSet(sets.WS.Default);
            end
        end
    end

me: wouldn't weapon skills show up in the HandleWeaponskill function?

Yes, many popular LuAshitacast profile frameworks use a dedicated profile.HandleWeaponskill function (or call it via custom event dispatchers)
rather than a raw profile.OnPrecast block.

Whether your profile hooks into profile.HandleWeaponskill or profile.OnPrecast, the underlying action table (gData.GetAction() or the action
argument) still exposes the exact same .Id and .Name parameters.

Implementing IDs inside HandleWeaponskill

If your specific template relies on profile.HandleWeaponskill, you can refactor it cleanly using an ID-based lookup table like this:

    -- Define your ID-to-modifier lookup table at the top of your file
    local ws_modifiers = {
        [240] = 'STR_MND', -- Savage Blade
        [32]  = 'STR_VIT', -- Asuran Fists
        [43]  = 'DEX_CRIT',-- Evisceration
        [85]  = 'STR',     -- Rampage
    }

    profile.HandleWeaponskill = function()
        -- Check your standard bailout/amnesia conditions first if your template uses them
        if (gcinclude and gcinclude.CheckWsBailout and gcinclude.CheckWsBailout() == false) then
            gFunc.CancelAction()
            return
        end

        local ws = gData.GetAction()

        -- Fallback default set
        gFunc.EquipSet(sets.Ws_Default)

        -- Lookup via ID instead of string matching
        local ws_type = ws_modifiers[ws.Id]
        if (ws_type == 'STR_MND') then
            gFunc.EquipSet(sets.Ws_Savage)
        elseif (ws_type == 'DEX_CRIT') then
            gFunc.EquipSet(sets.Ws_Evisceration)
        else
            -- Catch-all for unmapped IDs using standard gear
            gFunc.EquipSet(sets.Ws_General)
        end
    end

me: are there any weapon skills that completely ignore the stats on your gear?

On HorizonXI, there are no weaponskills that completely ignore all gear stats, but there is one legendary exception that completely ignores standard attribute
modifiers (STR, DEX, VIT, etc.) and enemy defense:

The Outlier: Spirits Within (ID: 232) / Spirit Taker (ID: 199)

Spirits Within (Sword) and Spirit Taker (Staff) utilize a unique damage formula that completely bypasses your standard stats (like STR or Attack) and structural
enemy defense.

    - The Formula: The base damage is computed entirely as a fixed percentage of your Current HP (scaled additionally by your TP).

    - What it ignores: Adding +STR, +DEX, +Attack, or Accuracy to your gear will provide 0% damage increase to the calculated hit.

    - How to gear for it: While it ignores standard offensive stats, it still scales off gear. To optimize it, you must swap into a specialized Max HP gear set.

Other "Stat-Ignoring" Sub-Categories

If you are auditing your configuration files for LuAshitacast, keep these secondary categories in mind:

1. Element-Based Magic Weaponskills

Weaponskills like Blade: Teki (ID: 162), Tachi: Jinpu (ID: 145), Red Lotus Blade (ID: 226), and Earth Crusher (ID: 194) deal purely elemental magic damage.

    - They completely ignore Your Attack, Melee Accuracy, and the Enemy's Physical Defense.

    - However, they do not ignore all stats; they scale based on Magic Attack Bonus (MAB), Elemental Affinity Gear, and standard dINT/dMND stat differences.

2. Flash / Stun / MP Drain Utility Weaponskills

Weaponskills like Flat Blade (ID: 227), Leg Sweep (ID: 131), Starlight (ID: 179), and Energy Drain (ID: 39) focus strictly on adding utility statuses or draining
static pools.

    -Their primary function completely ignores your standard damage attributes.

    - Instead, they scale exclusively with your base Weapon Skill Level (for accuracy/landing the status effect) and specific secondary elements (MND/INT for drains).

Implementation Advice for LuAshitacast

Because Spirits Within (ID: 232) relies on completely separate gearing philosophies compared to every other physical skill in the game, it is highly recommended to
isolate it completely in your script:

    if (ws.Id == 232) then
        -- Completely ignores STR/DEX; forces pure Max HP gear
        gFunc.EquipSet(sets.WS.MaxHP);
    end

me: if I'm using a BLU spell with chain affinity, I assume the id's are the spell's Id and not a weaponskill Id.

Correct. Your assumption is completely right.

Even when under the effects of Chain Affinity, the action you are executing is still technically a Magic Spell (action.Type == 'Spell'), not a weaponskill. Therefore,
LuAshitacast and AshitaCore will pass the Spell ID (e.g., Sprout Smack is ID 547, Sickle Slash is ID 563).

Because Chain Affinity causes physical Blue Magic to behave like a weaponskill for skillchains and consumes your TP, it changes your gearing requirements dramatically.

How to Handle This in Your Code

To track and gear these correctly using IDs, you want to inspect if the Chain Affinity buff is active when a spell is cast. You can achieve this cleanly by checking
the player's active buffs using the Ashita core buff data:

    profile.OnPrecast = function(action, bSpells)
        if (action.Type == 'Spell') then
            -- Check if player has the Chain Affinity buff active (Buff ID: 407)
            local player = gData.GetPlayer()
            local isChainAffinity = false

            for _, buffId in ipairs(player.Buffs) do
                if buffId == 407 then
                    isChainAffinity = true
                    break
                end
            end

            if isChainAffinity then
                -- This is a Chain Affinity Spell!
                -- Map the Spell ID to your physical scaling categories
                if (action.Id == 563) then -- Sickle Slash
                    gFunc.EquipSet(sets.CA_Spells.STR_VIT)
                elseif (action.Id == 547) then -- Sprout Smack
                    gFunc.EquipSet(sets.CA_Spells.STR_DEX)
                end
            else
                -- Standard Magic Midcast / Precast logic
                gFunc.EquipSet(sets.Precast.FastCast)
            end
        end
    end
