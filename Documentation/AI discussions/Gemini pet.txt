me: in luashitacast on horizonxi in HandlePetAction when a BST does the Ready ability, what does PetAction.Name evaluate to?

In Luashitacast on HorizonXI, when a Beastmaster (BST) uses a Ready move, PetAction.Name evaluates to the specific name of the pet command/move being executed
(for example: "Tegmina Buffet", "Razor Fang", "Fluid Toss", or "Foot Kick"), rather than the word "Ready" itself.

However, there is an important quirk in Luashitacast's packet handling you need to account for when writing your script:

The "Trailing Space" Quirk

By default, the packet data coming from HorizonXI often appends a hidden trailing space to the pet action's name. If your pet uses Tegmina Buffet, PetAction.Name
will actually evaluate to "Tegmina Buffet ".

Because of this, standard BST profiles in Luashitacast use string manipulation to strip that trailing character before checking it against physical or magical gear sets:

    profile.HandlePetAction = function()
        local petAction = gData.GetPetAction()

        -- Strip the trailing space quirk common in Horizon Luashitacast
        local actionName = string.sub(petAction.Name, 1, #petAction.Name - 1)

        -- Now actionName evaluates exactly to "Tegmina Buffet", "Razor Fang", etc.
        if PetPhysMoves:contains(actionName) then
            gFunc.EquipSet(sets.PetAtk)
        elseif PetMabMoves:contains(actionName) then
            gFunc.EquipSet(sets.PetMab)
        end
    end

To Swap Gear on the "Ready" Activation Itself

If you want to swap gear for the actual "Ready" command precast (to lower charges or augment the activation using things like Charmer's Merlin or Desultor Tassets), you
handle that inside HandlePrecast using the player's ability type:

    profile.HandlePrecast = function()
        local ability = gData.GetAction()

        -- This checks if the player is initiating the "Ready" command
        if string.match(ability.Type, 'Ready') then
            gFunc.EquipSet(sets.Ready_Charges)
        end
    end

me: what about if the bst does a sic?

When a Beastmaster uses Sic, PetAction.Name evaluates exactly the same way it does for Ready: it evaluates to the specific name of the move the pet randomly chooses to
execute (such as "Foot Kick", "Lamb Chop", or "Head Butt"), rather than the word "Sic".

Because Sic forces the pet to choose a move on its own based on its current TP, Luashitacast intercepts the actual incoming pet outgoing action packet. From the Lua's
perspective, whether you used Ready to choose the move manually or Sic to let the pet choose it randomly, the resulting pet action is what populates PetAction.Name.

Handling the "Sic" Trailing Space

Just like Ready, Sic moves are plagued by the exact same trailing space bug in HorizonXI's packet stream. If your pet randomly selects Foot Kick via Sic, PetAction.Name
will actually read as "Foot Kick ".

You should use the exact same string trimming logic inside your HandlePetAction function to capture both types of moves cleanly:

    profile.HandlePetAction = function()
        local petAction = gData.GetPetAction()

        -- This handles BOTH Ready and Sic moves cleanly by wiping the trailing space
        local actionName = string.sub(petAction.Name, 1, #petAction.Name - 1)

        -- Example lookup table check
        if PetPhysMoves:contains(actionName) then
            gFunc.EquipSet(sets.Pet_Physical)
        end
    end

Swapping Gear for the "Sic" Activation

If you are looking to swap into Sic Recast / Sic Reduction gear (like Beast Mitts or Stout Jerkin), you must do that during the player's activation step inside HandlePrecast.

Unlike Ready, which uses ability.Type == 'Ready', Sic is categorized natively as a standard Job Ability:

    profile.HandlePrecast = function()

        -- Swap gear for the actual character's "Sic" command activation

            gFunc.EquipSet(sets.Sic_Recast)
        end
    end

me: what about other commands like Stay or Heel?

For universal utility pet commands like Stay, Heel, Fight, or Leave, the behavior changes completely because these are player-directed master commands, not physical or magical
abilities executed by the pet.

    1. HandlePetAction will completely ignore them

        The HandlePetAction function in Luashitacast only intercepts outgoing abilities performed by the pet (like Ready moves, Sic moves, or Blood Pacts).

        When you use Stay or Heel, your pet does not use a TP move or an ability.

        Consequently, HandlePetAction does not fire at all, and PetAction.Name will not evaluate to anything for these commands.
    2. They are caught in HandlePrecast instead

        Because Stay, Heel, Fight, and Leave are commands executed by the player character, they are processed natively as incoming actions. You catch them inside HandlePrecast
        using gData.GetAction().

    When you trigger them, the master action properties evaluate exactly to their literal names:

    Player Command      action.Name evaluates to...     action.Type evaluates to...
    --------------      ---------------------------     ---------------------------
    /pet "Stay"             "Stay"                          "Pet Command"
    /pet "Heel"             "Heel"                          "Pet Command"
    /pet "Fight"            "Fight"                         "Pet Command"
    /pet "Leave"            "Leave"                         "Pet Command"

How to use this to swap gear

If you want to swap into a Pet Damage Taken (Pet: DT) / Pet Idle set when you order your pet to Stay (or swap to a high movement-speed set when you call them to Heel), you
handle it like this inside HandlePrecast:

    profile.HandlePrecast = function()
        local action = gData.GetAction()

        -- Check if it's a general pet command
        if action.Type == 'Pet Command' then
            if action.Name == 'Stay' then
                gFunc.EquipSet(sets.Pet_Idle_DT) -- Lock your pet down in defensive gear
            elseif action.Name == 'Heel' then
                gFunc.EquipSet(sets.MovementSpeed) -- Put yourself in movement gear while it runs back
            end
        end
    end

⚠️ A Crucial Difference for Blood Pacts

While the Fight command behaves the same as BST, Blood Pacts (Ward and Rage) deviate from BST's Ready moves in how Luashitacast reads them:

    1. Unlike Ready moves (which immediately execute as a pet action), when you use a Blood Pact, the SMN must first perform a player casting animation.

    2. Because of this, a Blood Pact will hit your player's HandlePrecast first as action.Type == 'Blood Pact Rage' or 'Blood Pact Ward'. This is where you equip your
       Blood Pact Delay Reduction gear.

    3. Only after your character finishes the command will HandlePetAction fire for the Avatar's actual move (e.g., Predatory Claws). This is where you swap to your
       Avatar's physical or magical damage gear.

Unlike BST (Ready) or SMN (Blood Pacts), Luashitacast has a notorious limitation when it comes to the Automaton's subsequent combat actions.

When your Automaton decides to execute a Weapon Skill (like String Shredder) or cast a spell (like Fire IV), the game handles this entirely server-side between the
pet and the monster. Because Luashitacast does not intercept outgoing Automaton physical execution packets the way it does for a BST pet, HandlePetAction will never
fire for Automaton Weapon Skills.

To swap gear for an Automaton Weapon Skill, PUP players typically use an Ashita addon (like TPActions or a custom helper) to look at the pet's TP/actions, or they
tie their mid-fight Automaton sets directly to their Master's macro buttons.

me: but doesn't HandlePrecast also handle the precast of Spells/Songs?

Yes, HandlePrecast handles absolutely every action your character initiates [1]—including Spells, Ninjutsu, Songs, Job Abilities, Weapon Skills, and Items.

Because HandlePrecast is a single catchment zone for all player actions, you separate them cleanly by wrapping your logic in conditional checks using action.Type
or action.Skill.

Here is how a standard profile organizes HandlePrecast so that your Job Abilities (like Steady Wing) don't conflict with your Spells or Songs:

Clean Structure for HandlePrecast

    profile.HandlePrecast = function()
        local action = gData.GetAction()

        -- 1. Handle Spells & Ninjutsu (Fast Cast gear)
        if action.Type == 'Magic' or action.Type == 'Ninjutsu' then
            gFunc.EquipSet(sets.FastCast)

        -- 2. Handle Bard Songs (Song Precast gear)
        elseif action.Type == 'BardSong' then
            gFunc.EquipSet(sets.SongPrecast)

        -- 3. Handle Weapon Skills (WS specific gear)
        elseif action.Type == 'WeaponSkill' then
            gFunc.EquipSet(sets.WS[action.Name] or sets.WS_Default)

        -- 4. Handle Job Abilities (Steady Wing, etc.)
        elseif action.Type == 'Job Ability' then
            if action.Name == 'Steady Wing' then
                gFunc.EquipSet(sets.Steady_Wing)
            elseif action.Name == 'Spirit Link' then
                gFunc.EquipSet(sets.Spirit_Link)
            end
        end
    end

The Universal Execution Pipeline

To visualize why Steady Wing goes here and why your Wyvern's Breaths do not, here is how Luashitacast steps through a player action vs a pet action:

    1. Player hits a Macro (Spell, Song, or JA like Steady Wing) → HandlePrecast fires (Equip Fast Cast / JA Augments) → HandleMidcast fires (Only for Spells/Songs
       to equip potency gear) → HandlePreshot/Midshot (Only for Ranged attacks).

    2. Wyvern reacts with a Breath → HandlePetAction fires (Equip Wyvern Potency/Breath gear).

Since Steady Wing is structurally just a Job Ability, it gets handled alongside your standard physical actions before any magical casting ever touches your script.

me: So, gData.GetPetAction is just a subfunction that luashitacast is doing to isolate pet commands.

Under the hood, gData.GetPetAction() isn't just isolating the master commands you type—it is actually doing something much cooler. It is looking at a completely
different network packet stream coming from the server.

When you use Luashitacast on HorizonXI, the system splits actions into two totally separate data feeds:

    1. gData.GetAction() (Player Stream): This captures the network packets generated by your character. This includes your spells, your songs, your Job Abilities,
       and your master /pet macros (like Fight or Stay).

    2. gData.GetPetAction() (Pet Stream): This captures network packets generated specifically by your pet or avatar.

Because your pet is technically an independent entity in the game world, its combat animations and TP moves are broadcast on a separate frequency.
Data.GetPetAction() is Luashitacast's built-in helper function to listen to that pet frequency.

Why the Distinction Matters for Your Code

Because these two streams are completely separate, Luashitacast routes them to different blocks:

    - Player Macros flow into HandlePrecast and are read using gData.GetAction().

    - Pet-Executed Abilities (like Tegmina Buffet, Razor Fang, or Predatory Claws) flow into HandlePetAction and are read using gData.GetPetAction().

If you ever try to call gData.GetPetAction() inside your normal HandlePrecast loop, or try to call gData.GetAction() inside HandlePetAction, the script will
usually return nil or crash because the data isn't there.

me: reviewing what you said earlier, it sounds like I can tell on a DRG when my wyvern will do a breath weapon.

Yes, you can, but there is a crucial timing limitation to how FFXI handles Wyvern Breaths that changes how you write your code.

While HandlePetAction will perfectly detect when your Wyvern is executing a breath (evaluating PetAction.Name to things like "Healing Breath", "Healing Breath II",

calculated the potency based on the gear you were wearing when the breath was triggered.

Because of this system lag, you cannot swap into Wyvern gear inside HandlePetAction and expect it to boost the breath. You have to predict and catch it a step earlier.

How to Actually Automate Wyvern Breaths

To successfully buff a Wyvern Breath, you must swap your Wyvern gear on during your own spell's midcast loop, right before the Wyvern reacts.

The strategy relies on tracking the type of spell you cast while your character is subjobbed as a Mage (like White Mage, Red Mage, or Ninja):

    1. Your Precast: You cast a spell (e.g., Dia or Barfira). You equip Fast Cast gear.

    2. Your Midcast (HandleMidcast): This is where you intercept it. You check if you are low on HP (for a Healing Breath) or if the spell is offensive (for a Smiting
       Breath). If the criteria are met, you equip your Wyvern: HP+ or Breath+ gear right here.

    3. The Execution: Your spell finishes casting, which instantly triggers the Wyvern's breath while you are already wearing the correct gear.

    4. The Cleanup: You return to normal TP/Idle gear.

The Implementation Script

Here is how you structure your HandleMidcast to force your Wyvern gear onto your character right before the breath triggers:

    profile.HandleMidcast = function()
        local action = gData.GetAction()
        local player = gData.GetPlayer()

        -- 1. Check for a Healing Breath trigger
        -- Typically triggers when you cast any magic while below 33% HP (or 50% with Wyvern Helm)
        if (action.Type == 'Magic' or action.Type == 'Ninjutsu') and player.HPPercent < 50 then
            gFunc.EquipSet(sets.Wyvern_Healing_Breath) -- Maximize Wyvern HP+ for huge cures
            return -- Exit early so standard magic sets don't overwrite this
        end

        -- 2. Check for an Elemental / Smiting Breath trigger
        -- Triggers when you cast offensive magic (like Dia) while the pet is engaged
        if action.Type == 'Magic' and (action.Name == 'Dia' or action.Name == 'Bio') then
            gFunc.EquipSet(sets.Wyvern_Smiting_Breath) -- Maximize Breath Potency gear
            return
        end

        -- 3. Default Magic Handling (if no breath is expected)
        if action.Type == 'Magic' or action.Type == 'Ninjutsu' then
            gFunc.EquipSet(sets.Magic_Default)
        end
    end
