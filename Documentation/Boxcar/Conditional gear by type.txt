The following lists all of the conditional inline checks, grouped by type. Note: some conditionals
have had their names changed, for consistency purposes. Also, many inverted conditionals have been
added to represent the opposite of an existing conditional. These are all prefixed with: NOT_. You'll
notice that not all conditionals have an inverted version. This is because either I fealt that an
inversion made no sense or there's another conditional that has the same meaning.

Conditional:
    //HP.conditional.#       Equip if conditional is found true for HP
    //HPP.conditional.#      Equip if conditional is found true for HP%
--    //HPPA.conditional.#     Like HPP, but it uses a standard max HP% for the specific gear set
    //MP.conditional.#       Equip if conditional is found true for MP
    //MPP.conditional.#      Equip if conditional is found true for MP%
--    //MPPA.conditional.#     Like MPP, but it uses a standard max MP% for the specific gear set
    //TP.conditional.#       Equip if conditional is found true for TP
    //TPP.conditional.#      Equip if conditional is found true for TP%
    //LVL.conditional.#      Equip if conditional is found true for the primary job's level
    //PARTY.condition.#      Equip if party number meets conditional criteria
    //PETHPP.conditional.#   Equip if pet's HP% meets the comparison
    //LVLDIV:#               Equip if the primary job's level is evenly divisible by #
    //NOT_LVLDIV:#           Equip if primary job's level does not evenly divide by #

    Valid conditionals are -
        .EQ.            Equal to
        .GT.            Greater than
        .GE.            Greater than or equal to
        .LT.            Less than
        .LE.            Less than or equal to
        .NE.            Not equal to

Spells/Songs:
x    //SPELL:xxx,...         Equip if spell's name matches one of the attached spells            //NOT_SPELL:xxx,...      Equip if the spell's name does not match any of the attached spells
x    //SPELL_ROOT:xxx,...    Equip if spell's root matches one of the attached roots             //NOT_SPELL_ROOT:xxx,... Equip if the spell's root does not match any of the attached roots
x    //SPELL_SUB:xxx,...     Equip if spell's name contains one of the attached substrings       //NOT_SPELL_SUB:xxx,...  Equip if cast spell's name does not contain one of the attached substrings

x    //SONG:xxx,...          Equip if cast song name matches one of the attached songs           //NOT_SONG:xxx,...       Equip if the cast song does not match any of the listed songs
x    //SONG_ROOT:xxx,...     Equip if cast song's root matches one of the attached roots         //NOT_SONG_ROOT:xxx,...  Equip if cast song's root does not match any of the listed roots
x    //SONG_SUB:xxx,...      Equip if cast song's name contains one of the attached substrings   //NOT_SONG_SUB:xxx,...   Equip if cast song's name doesn't contain any of the attached substrings

    Note: Spell's root conveys the same type of information that a song's type does. A spell's "root" is the first word in the spell's name, a song's "type" tends to be the second word or an
    agreed upon classification. If I implemented SPELLTYPE like SONGTYPE, it would result in the same list of words found in SPELL_ROOT, so it's not necessary. As to SONG_ROOT, I'm not sure that
    is really useful, but since it is different than the SONGTYPE, I have implemented it.
